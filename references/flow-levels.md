# Flow Levels

默认自动分级，不要求用户手动选择。用户可以显式覆盖：`quick / standard / strict`。

## quick

适用：

- 文案修改。
- 样式微调。
- 小范围配置。
- 单文件无业务逻辑改动。
- 开发辅助脚本。
- 不影响用户行为的轻维护。

流程：

- 不创建 PRD / REQ。
- 不读完整历史文档。
- 简单验证和自查。
- 必要时只创建或更新 TASK。
- 不自动 commit，进入人工审核。

quick 禁用场景：

- PRD / 产品文档。
- 现有功能改版。
- 多模块改动。
- 接口变化。
- 数据结构变化。
- 权限 / 支付 / 订单 / 登录等核心链路。
- 部署 / 配置 / 监控变化。
- 用户要求完整流程。

## standard

适用：

- 普通 Bug。
- 普通功能调整。
- 单模块功能。
- 有明确验收标准。

流程：

- Bug：`BUG + TASK + ACC`。
- 普通功能：`TASK + ACC`，必要时 PRD。
- 优先 TDD；无法自动化则写手工验收。
- 验证、代码审查、文档同步、人工审核。

## strict

适用：

- PRD / 产品文档。
- 现有功能改版。
- 多模块或高风险改动。
- 架构、接口、数据模型、权限、支付、订单、登录。
- 部署、配置、监控、回滚变化。

流程：

- 新功能 / 改版：`PRD + REQ + TASK + ACC`。
- 必要时 `ADR / design / ops / legacy`。
- REQ 未经人工确认前不编码。
- TDD 或明确手工验收项。
- 必要时 subagent 或人工独立 review。

## 自动升级

从最低必要流程开始。一旦发现风险条件，自动升级并说明原因：

```text
本次从 standard 升级为 strict，原因：发现接口契约变化。
```

如果任务类型不确定，默认 `standard`，不要用 `quick`。
